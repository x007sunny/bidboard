# Bidboard P0 fixes

This zip is the existing Bidboard app plus **only** these four P0 changes.

## 1. Bid race

**Bug:** checkout read `listing.bidCents`, Stripe charged the delta, then the webhook *set* `bidCents = metadata.newBidCents`. Two overlapping checkouts both saw the same current bid, both paid, and the last write won. Paid money vanished from the rank.

**Fix:** webhook transaction takes `SELECT … FOR UPDATE` on the listing (or `uniqueKey`), then **adds** `payment.amountCents` to the current bid. Concurrent paid sessions stack. Serializable isolation plus the unique `uniqueKey` covers two first-time claims of the same URL.

## 2. Real visitors

**Bug:** homepage used `1327 + hoursSinceLaunch * 12` and a random “online” number.

**Fix:** `Visitor` rows keyed by an httpOnly `bb_vid` cookie. `VisitBeacon` pings `POST /api/visit`. Header counts `Visitor` rows (total) and `lastSeenAt` within 5 minutes (online). Obvious bots are skipped.

## 3. SSRF

**Bug:** metadata fetch followed redirects to whatever host the user URL resolved to. Hostname checks missed DNS rebinding, IPv6 ULA/link-local, CGNAT, and cloud metadata.

**Fix:** `src/lib/safeFetch.ts` resolves DNS, rejects private / reserved IPs (IPv4 + IPv6), blocks metadata hosts, and follows at most 3 redirects with the same check on every hop. `fetchWebsiteMetadata` uses it.

## 4. Stripe webhook idempotency

**Bug:** Stripe retries `checkout.session.completed`. The handler always updated the payment and listing again.

**Fix:** `StripeEvent.id = event.id` is inserted in the same transaction as the listing/payment write. A duplicate `evt_…` hits the unique constraint and returns 200 without applying side effects. Processing errors still return 500 so Stripe can retry a rolled-back attempt.
